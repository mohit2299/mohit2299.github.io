Size curve review

RSQLExcel
The problem
Sizes were stocked differently from how they sold, leaving too much in some and too little in others.
What I built
A framework that compares sales run rate, inventory and planned buy curves by size, flags the gaps, and recommends buy corrections and moves from existing stock before new production.
The result
A repeatable size review, and a next-season size curve package for planners.

Extended sizes

SQLAnalysis
The problem
Nobody had a clear view of demand for the largest and tallest sizes.
What I did
Measured demand by size, franchise and color family, and separated sizes that justified replenishment from those that did not.
The result
Buying decisions based on what each extended size actually sold.

Aged inventory ranking

RExcel
The problem
Old stock was known, but there was no agreed order for which units to move first.
What I built
A framework that scores items by projected age, sorts them into four action tiers, and applies planned clearance oldest-first. It refreshes from supplier files on a regular cycle and ships with a runbook.
The result
One shared priority list, and a large block of old inventory worked down over months.

Reorder tool

RSQLPower BI
The problem
Planners assembled reorder inputs by hand from several supply sources with different keys.
What I built
One view across five supply nodes, a safety stock rule with a floor, and a split between real excess and necessary buffer.
The result
A single consolidated view and projected year-end inventory below the prior year.

E-commerce demand forecast

PythonRegressionDatabricks
The problem
Planners needed a daily demand forecast for the app and the website that could take promotions and paid spend as inputs.
What I built
A model that forecasts traffic, conversion and order value separately and multiplies them, with spend inside the model and Monte Carlo ranges. I tested it by refitting on past dates and checking it on months it never saw, and wrote a handover guide with automated run checks.
The result
On a held-out period it beat benchmarks built from last year's sales. It also showed where it was weak: it over-forecast recently, and the simpler models were hard to beat.

Supply chain optimization

PythonReinforcement learningFolium
The question
Could an agent learn to predict whether a delivery will be on time, and could a planner order a list of cities into a sensible route?
What I built
A Deep Q-Network agent in a custom environment that predicts delivery status on a public Kaggle supply chain dataset, using experience replay and an epsilon-greedy policy. A second tool geocodes a list of cities, orders the stops with a nearest-neighbour heuristic on Haversine distances, estimates travel days at a set daily mileage, and draws the route on an interactive map.
What I would improve
The route is a heuristic and does not guarantee the shortest path, so I would add 2-opt local search and real constraints such as delivery windows. The agent is sensitive to tuning, and a plain classifier is the baseline it should be compared against.
